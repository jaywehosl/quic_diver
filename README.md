# QUIC Diver

Прозрачный TUN-less прокси. Единое Go-ядро на всех ОС (кроме захвата пакетов).
Транспорт клиент↔узел — QUIC + MASQUE.

Модель data-path — **B (connect-ip)**: клиент тонкий (заворачивает сырые IP в
connect-ip датаграммы), gVisor+netstack живёт на узле. Развилка заперта в
`engine.Engine`, поэтому модель **A** (терминация L4 в gVisor на клиенте)
добавляется позже без переделки.

## Как это выглядит в работе

```
клиент ──QUIC──> узел-вход ──QUIC──> узел-выход ──> интернет
        (TCP: CONNECT-стрим, RFC 9114 / 9220)
        (UDP: CONNECT-UDP, RFC 9298)
        (прочее: connect-ip датаграммы, RFC 9484)
```

Маршрут едет **меткой в самом флоу** (`Qd-Route`): `direct`, идентификатор узла
или `auto:<тег>`. Каждый хоп читает метку и решает сам — он выход или транзит.
Ручных связей между узлами нет: узлы равны и берут соседей из общей реплики.

**Недостижимый выход никогда не глушит флоу** — трафик уходит наружу с текущего
узла. Пользователь остаётся со связью, пусть и не из той страны; администратор
узнаёт об отступлении из журнала.

## Сеть узлов

Один бинарь `qd-server` — роль определяется конфигом, не кодом.

| Механизм | Как устроен |
|---|---|
| Реестр узлов | у мастера, расходится репликой; у каждого узла свой токен, у соседей — только его хеш |
| Репликация | реплика тянет снимок (`VACUUM INTO`) и применяет **без перезапуска** — рестарт рвал бы туннели |
| Мастер | поколение (`epoch`) против split-brain; промоушен только вручную admin-токеном |
| Живость | стук раз в минуту; он же несёт отчёт о трафике снизу вверх |
| Балансировка | `auto:<тег>` выбирает по `SRTT + 2·RTTVAR + потери`, с гистерезисом и cooldown |
| Учёт | расход считается по всей сети (сумма по узлам), лимит — ГБ за период |

Добавление узла — одна команда: регистрируешь узел в admin-API, получаешь
готовую строку, выполняешь её на чистой машине. Дальше узел сам забирает у
мастера реестр, клиентов и admin-токен.

## Ключевые контракты

| Пакет | Контракт | Роль |
|-------|----------|------|
| `internal/packet` | `Source` | batch recv/send сырых IP; WinDivert (Win) / TUN (проч.) |
| `internal/uplink` | `Conn`, `Dialer` | QUIC/H3 до узла; datagram+stream; миграция |
| `internal/engine` | `Engine` | модель обработки; B=`hybrid`/`connectip`, A=позже |
| `internal/routing` | `Route` | разбор метки `Qd-Route` и решение «выход или транзит» |
| `internal/guard` | `Guard` | не захватывать локалку + анти-петля |
| `internal/server/db` | `Store` | SQLite; репликация, горячая подмена, backup/restore |
| `internal/server/decoy` | — | «under construction» на TCP:443 — снаружи обычный сайт |

## Сборка

Сначала — пропатченный quic-go (в git не хранится, `go.mod` на него `replace`):

```sh
sh scripts/setup-third-party.sh
go build ./...
```

Без первого шага сборка падает на `replacement directory ./third_party/quic-go
does not exist` — это ожидаемо.

### Зачем патч quic-go

- **Очереди DATAGRAM 32/128 → 256/1024.** Upstream рассчитан на редкие
  сигнальные датаграммы: send-очередь на 32 вводит отправителя в stop-and-go,
  rcv на 128 молча дропает при всплеске. У нас датаграммы несут ВЕСЬ IP-трафик,
  дроп = потеря пакета = внутренний TCP рушит cwnd. Сильнее раздувать нельзя:
  длинная очередь — это bufferbloat.
- **`quic.DatagramStats()`** — иначе потери внутри quic-go невидимы.
- **Cubic вместо Reno.** Upstream хардкодит Reno, а тот делит окно пополам на
  каждой потере и растёт линейно.
- **BRUTAL congestion** (`QD_BRUTAL_MBPS=N`): слать с заданной полосой, игнорируя
  потери. Измерено на плече 850 км: loss-based CC отдавал 458–561 Мбит при
  потерях 0.016–0.27%, brutal — 694 (сырой UDP по тому же пути — 756). Ставить
  НИЖЕ реальной полосы, иначе очереди и рост RTT. Нужен на обоих концах.

## Запуск

Узел (dev, без БД — открыт, только для локальных проверок):

```sh
go run ./cmd/qd-server -listen :8443 -authority localhost:8443
```

Узел боевой — с БД, токенами и сертификатом:

```sh
qd-server -listen :443 -authority node.example -db /opt/quic-diver/node.db \
	-admin-token <admin> -node-token <свой> \
	-cert fullchain.pem -key privkey.pem
```

Первый узел сети становится мастером сам. Остальные ставятся установщиком.

## Диагностика

`cmd/qd-devtest/` — инструменты, не требующие администратора:

- `qdflood` — изолятор транспорта: чистый QUIC-datagram без connect-ip/gVisor.
  Меряет throughput+stddev, СЕТЕВЫЕ потери (по seq) и RTT под нагрузкой
  (bufferbloat). Эталон, с которым сравнивается полный тракт.
- `qddial` — connect-ip туннель + настоящий DNS-запрос через него.
- `qdtcp` — TCP-флоу через узел с меткой маршрута (`-route`).
- `qdadmin` — admin-API: `-nodes`, `-path /qd-admin/...` для любого эндпоинта.
- `qd-client`/`qd-server` — флаг `-pprof addr` для профиля под нагрузкой.

Релизный клиент — один `.exe`: веб-панель (`embed.FS`) и WinDivert `.dll`/`.sys`
вшиты, распаковка в `%APPDATA%\QUICDiver`.

admin-API поверх QUIC.
